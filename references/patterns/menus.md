Menus is a product-level pattern (status beta, last updated 2026-09-10, not in the component registry): actions for a resource, page, or canvas selection, revealed through a kebab button, a dropdown button, or a context menu. It is a floating white panel of command rows with optional icons, shortcuts, dividers, danger rows, checkbox rows, and one-level submenus. It comes from the site's /patterns/menus page, which was written from the Designer codebase (FlowX DS Gap Audit of September 4, 2026, recommendation #4, reviewed against Designer checkout 01326458d3 on September 10, 2026), so every palette mapping is a code-derived equivalent rather than a verified Figma binding and there is no Figma component link. Three menu types are documented. Kebab (standard density) keeps secondary resource actions close to their row behind a named DotsThreeVertical icon button (20px, bold); its example lists Copy UUID (CopySimple), Details (PencilSimple), Audit Logs (ClockCounterClockwise), a divider, and Delete (TrashSimple, danger), and opening a row menu must not select or navigate the row. Dropdown (standard density) groups commands under a visible action label such as "Manage resources" with a trailing 16px CaretDown; its example is Import (UploadSimple) with children from CSV and from ZIP, and Export (DownloadSimple) with children to CSV and to ZIP. Context (compact density) offers commands for the current canvas selection at the pointer via right-click, Shift+F10, or the ContextMenu key, paired with a visible "Actions" button that opens the same commands below the button for touch and keyboard users; its example is Copy (⌘C or Ctrl+C), Paste (⌘V or Ctrl+V, disabled), a divider, Apply To with the checkbox children Contact details (checked) and Review application (unchecked), a divider, and Delete (⌫ or Delete). Icons are not shown in the context examples; the playground disables the icons toggle for Context. The item props are label (a concise action or destination; a submenu label names the group), icon / iconName (optional leading icon; resource menus use icon, the context wrapper supports iconName), command (runs an action for the current resource; ordinary actions close the menu, checkbox actions can keep it open), disabled (default false; keeps an unavailable action visible and prevents activation, explain the prerequisite in the surrounding UI), visible (default true; hides actions that do not apply to the resource or permissions, removing empty groups and unused dividers as well), separator (default false; a non-interactive divider between meaningful groups, never between every item), items (child actions in a submenu; the parent opens the group and does not also run a command), shortcut / shortcutIcon (context-menu hints for shortcuts the application actually supports, in the correct platform notation), subheader (default false; a small non-actionable group heading in the context wrapper), checkbox / checked (default false; context wrapper extensions used by Apply To, where a checkmark communicates a persistent on/off choice), and danger-cta (the resource menu style class for destructive actions, currently coloring label and icon Red 400).

The anatomy is a trigger (a labelled button, a named kebab button, or the selected canvas object, retaining the resource context until dismissal), the panel (a floating white surface with 8px padding, 8px corners, and a shadow, whose width follows content within the viewport), action rows (optional icon, label, and optional shortcut or submenu caret, with the whole row as the target), group headings and dividers (which separate related actions without behaving like actions), a danger row (a destructive command in a separate final group, where color reinforces an explicit label), and a submenu (a second panel for child commands or checkbox choices, reachable without crossing another row). The panel is #ffffff (grays/50) with no border (no stroke is defined or rendered), 8px padding on all sides, an 8px corner radius, and Open Sans (var(--font-flowx)). Its standard shadow is 2px 2px 24px at 8% of the #163462 ink (color-mix on the local --flowx-menu-shadow-ink, the same ink as the elevation shadowColor), which resolves to 2px 2px 24px rgba(22, 52, 98, 0.08) and matches the Primary card shadow rather than an elevation level; the compact shadow is the heavier source stack of 0 2px 4px -1px rgba(0, 0, 0, 0.20), 0 4px 5px rgba(0, 0, 0, 0.14), and 0 1px 10px rgba(0, 0, 0, 0.12) (grays/900 at 20%, 14%, and 12%). There is no width token: the standard specimen is 224px wide (illustrative only, width follows the longest label and its trailing content), the compact specimen is 200px (context menus start at a 200px minimum), specimens cap at 100% of their container, and live popups cap at min(320px, available width) with a max-height of the available height and overflow-y auto so long lists scroll inside the panel. The positioner sits at z-index 70. Every row is wrapped in a 2px inset on all sides, so row pitch is the row's min-height plus 4. A standard row is a horizontal flex, vertically centered, with an 8px gap, 4px 8px padding, a 6px corner radius, and a 28px min-height (32px pitch); a compact row has the same 8px gap with 2px 4px padding, a 4px corner radius, and a 20px min-height (24px pitch). The optional leading icon is 16x16 (toggleable through the Icons property, visible by default); the label takes flex 1 with min-width 0 and overflow-wrap anywhere so it wraps in constrained widths; the shortcut and the 16px CaretRight submenu caret are pushed to the end of the row with margin-left auto; a divider is 1px tall with 4px vertical margin; the keyboard focus outline is 2px solid at outline-offset -2px. The docs playground trigger buttons (illustrative only; real triggers are Button component instances) are min 36x36 with 6px 8px padding, an 8px gap, a 1px solid #cbd1db (neutrals/200) border, 8px radius, #ffffff background that turns #f7f8f9 (neutrals/50) on hover or while open, #2a313a (neutrals/800) 600 12px/20px text, a 2px solid #006bd8 focus outline at offset 3, a DotsThreeVertical 20px bold kebab icon, and a CaretDown 16px dropdown caret.

Typography is Open Sans throughout. Standard labels are 14px with a 20px line-height at weight 600; compact labels are 12px/16px at weight 400; shortcut hints are 12px/16px at weight 400; subheaders are 10px/15px at weight 600. Resource actions add the 600 weight through their menu factories while the base dropdown stylesheet only sets 14px, and the type must never be shrunk to fit more actions. Light colors: standard rows have a transparent default fill with #475263 (neutrals/700) text and #2a313a (neutrals/800) icons at full opacity; hover fills the row #f7f8f9 (neutrals/50); focus fills #f7f8f9 and adds the 2px solid #006bd8 (blue/500) inset outline; disabled keeps the transparent fill and unchanged text color but drops the whole row to 0.5 opacity, shows a not-allowed cursor, and gets no hover fill; danger colors label and icon #eb4e33 (red/400) on a transparent fill and still takes the neutrals/50 hover fill; a submenu parent shows the #f7f8f9 fill while open or highlighted with a CaretRight that inherits the row text color; checked rows fill #e6f0fb (blue/50) with #006bd8 label and icon (defined for standard density in the data but only used by compact Apply To rows in the examples). Compact rows follow the same model with #000000 (grays/900) text, #2a313a icons, the same #f7f8f9 hover and focus fill and blue/500 outline, a disabled opacity of 0.25 (the source's value), a red/400 danger definition that the rendered context example does not apply to Delete because the reviewed canvas Delete has no danger class, and checked rows in #e6f0fb with #006bd8 text and a fill-weight CheckSquare icon, while an unchecked checkbox row shows a regular-weight Square in #2a313a. Shortcut text is #64748b (neutrals/500), dividers are #e3e8ed (neutrals/100), subheaders are #8390a2 (neutrals/400), and the focus ring is #006bd8 (blue/500). No dark treatment is documented: no shared dark-menu treatment has been verified, and because the palette variables the menu uses are not overridden in the site's dark theme, the panel renders the same light values in both themes. Item types, restated: an action (optional 16px icon, label, whole-row target, closes the menu on activation, role menuitem); a disabled action (visible at 0.5 or 0.25 opacity, not-allowed cursor, no hover fill, aria-disabled); a danger action (red/400 label and icon, alone in a final group after a divider); a submenu parent (trailing 16px CaretRight, opens its child panel on hover or Right arrow, never runs a command, neutrals/50 fill while open); a checkbox item (persistent on/off choice, Square when unchecked and fill-weight CheckSquare when checked, blue/50 fill and blue/500 text when checked, stays open after toggling, role menuitemcheckbox with aria-checked); a shortcut hint (trailing 12px/16px regular neutrals/500 text, aria-hidden, context menus only, platform notation); a divider (1px neutrals/100 line with 4px vertical margin, non-interactive, only between meaningful groups); and a subheader (compact context-menu group heading, 10px/15px weight 600 in neutrals/400, non-actionable, defined in the spec data only with no rendered specimen).

Behavior. Button menus open below their trigger (side bottom), aligned to the trigger's end edge (align end), with a 4px offset and 8px collision padding, and flip above when there is not enough room; context menus open at the pointer with a 2px offset and 8px collision padding, and keyboard opening moves focus to the first menuitem; submenus open beside their parent row (side right, align start) with a 4px offset and 8px collision padding, flip to the other side near a screen edge, stay within the viewport vertically, and must keep the pointer path into the child panel clear, and opening a submenu never runs its parent action. Keep the panel inside the viewport, wrap long labels when width is constrained, and scroll long lists within the panel. Popups animate over 120ms on opacity and transform, entering and leaving at opacity 0 and scale 0.98, with the transition disabled under prefers-reduced-motion. Dismissal rules: keep one root menu open at a time (opening a button menu closes an open context menu and vice versa); an ordinary command, an outside click, Escape, or leaving with Tab dismisses the menu; Escape from a submenu returns to its parent; checkbox choices in Apply To keep the menu open for repeated changes; close the menu when the page scrolls (wheel) away from its target but keep it open when the wheel event is inside the menu itself; when a shared popup opens for a different resource, update both its actions and its position; after dismissal keep keyboard focus in the triggering context (the trigger, or the canvas target for context menus), and if an action opens a dialog, move focus into that dialog and return it appropriately when the dialog closes. Keyboard: Enter or Space opens a button menu or activates an item; Up and Down move through items; Home and End jump to the first or last item; Right and Left open a submenu or return to its parent; Escape closes the current menu and returns focus to its trigger or parent; Tab and Shift+Tab close the menu and move through the page; typing letters finds an item by its label; Shift+F10 opens the context menu on the focused canvas object. Accessibility: role menu, menuitem for commands, and menuitemcheckbox for persistent toggles; aria-label names icon-only triggers and the menu's context; aria-haspopup and aria-expanded expose the trigger's menu and open state; aria-disabled identifies unavailable items and prevents activation; aria-checked exposes a checkbox item's value; focus-visible is the 2px solid blue/500 outline at offset -2px on the row, and decorative icons, shortcuts, and carets are aria-hidden. References are the W3C APG menu button and menubar patterns and WCAG 2.2 contrast minimum.

Usage guidance. Do keep resource actions beside the resource with a kebab for secondary actions such as Details, Copy UUID, and Delete while the main task stays visible in the page; name a group of commands with a labelled dropdown and use a submenu when an action needs one more choice, such as Export to CSV or ZIP; act on the current canvas selection with a context menu offering Copy, Paste, and Delete at the pointer plus a visible actions button for the same commands; separate destructive actions by placing Delete in a final group after a divider with a clear label and danger color, and when deletion needs confirmation, close the menu and open an alert that names the affected resource; keep unavailable actions visible but disabled and explain the prerequisite in the surrounding UI; hide actions that do not apply to the resource or permissions and remove empty groups and unused dividers with them; show shortcut hints only for shortcuts the application supports, in the correct platform notation; use the standard density for resource and page actions (compact documents the existing canvas context menu); and keep the panel inside the viewport, wrapping long labels and scrolling long lists. Don't let opening a row menu select or navigate the row, don't add a divider between every item, don't make a submenu parent also run a command, don't nest beyond one level where it can be avoided, don't shrink the type to fit more actions, and don't rely on color alone for a destructive action, since the label and icon still need to name it clearly.

Precedence against the dropdown-panel component (components/dropdown-panel.json, alias tree): they are different things and each governs its own case. If the rows run commands (Details, Copy UUID, Export, Delete) and the panel closes on activation, Menus governs, with its 8px panel padding and corners, 28px/20px min-height rows with 6px/4px corners, 600-weight 14px standard labels, red/400 danger rows, dividers, and card-style shadow. If the rows pick a value that persists as a selection (single or multi-select with checkbox or radio indicators, a select-all and search header, grouping of options), dropdown-panel governs, with its 244px/200px panel, 32px/24px rows, 4px row corners, and 0 8px 16px shadow. A persistent on/off toggle inside an action menu (Apply To) stays a menuitemcheckbox row styled by Menus and does not turn the panel into a dropdown-panel; the Designer's form-bound Nested Select is a selection control, not the action-menu reference. Where the two overlap (hover fill neutrals/50, checked or selected fill blue/50 with blue/500 text) the values coincide, so there is no color conflict, but never mix their dimensions within one panel. Menu triggers are Button component instances (the playground's trigger values are illustrative); a destructive action needing confirmation closes the menu and hands off to the Alerts pattern, other dialogs opened from a menu follow the Modals pattern, and the Select Field component's own option list is not a menu. Related components are button, select-field, tree, and checkbox; related patterns are alerts, modals, and page-anatomy.

Considerations and decisions. Red 400 on white is below the 4.5:1 reference for small text, so review a darker danger token before treating the current appearance as an accessibility-approved baseline. Destructive color is inconsistent across implementations (resource menus apply Red 400, the reviewed canvas Delete has no danger class), and the context preview preserves that difference while the guidance proposes identifying destructive actions consistently. The documentation chose a Blue 500 keyboard outline, 50% disabled opacity for standard rows, and the source's 25% for compact rows, where the compact source instead has a custom pale-blue focus shadow, mixed gray active-row colors, and shortcut text at 50% opacity; the preview uses FlowX neutrals for the active fill and shortcut text. The previews retain the light surfaces, source typography, spacing, and separate shadows per density. The 4px button and submenu gap, wrapping in constrained widths, the visible context actions button, and scrollable long panels are documentation guidance, whereas the reviewed resource alignment can be flush, the context submenu uses a 106% offset, and the source wheel handler closes even when scrolling a menu. The playground's keyboard navigation, checkbox semantics, focus return, named triggers, and collision-aware positioning demonstrate the intended contract without establishing parity in every PrimeNG and PrimeReact implementation, and the inline actions cell and form-bound Nested Select are adjacent patterns, not menu implementations. Decision log (2026-09-10): the pattern was documented from code rather than Figma, with illustrative resource names and compositions and no approved exception asserted; and two densities were kept, Standard from the dropdown and tiered menu source (8px panel padding and radius, 2px item inset, 8px by 4px row padding, 6px row radius, 14px labels, blue-ink shadow) for resource and page actions, and Compact from the canvas context menu source (200px minimum width, 12px labels, 4px by 2px row padding, 4px row radius, 25% disabled opacity, shortcuts, subheaders, checkbox rows).

Values not specified in the sources: any dark theme treatment (the palette variables are not overridden in dark mode); a panel width token (224px is illustrative, 200px is the context minimum, live popups cap at min(320px, available width)); subheader padding, margin, or casing and any rendered subheader specimen; a submenu caret color token (it inherits the row text color); trigger styling as a spec'd element (the 36px demo button belongs to the playground, real triggers are Button instances); a disabled text color (only opacity changes); a rendered red danger row in compact context menus; a replacement for the below-contrast red/400 danger color; a rendered standard-density checked row; any Figma link, node, or variable bindings; formal considerations, knownExceptions, or decisionLog fields in the spec (the ones above come from the page's Adoption notes and Source evidence); a maximum item count, scroll threshold, or hard nesting limit; icon color for compact rows with icons beyond the data value of neutrals/800; and source-verified offsets (the documented 4px trigger and submenu offsets, 2px context offset, and 8px collision padding are preview values, while the source aligns resources flush and offsets the context submenu by 106%).
