Toast (alias: toasts; the old /patterns/toasts page now redirects to /components/toast) is a beta component, last updated 2026-09-07, that gives brief feedback about an action or event, shown above the page without interrupting the current task. It documents the current unthemed Angular Toast used by Designer; its palette tokens are existing palette equivalents of the toolkit SCSS values, not extracted Figma bindings, and no Figma component link has been verified. It accepts the following props: messageType (required enum of "success", "warning", "info", or "error", which sets the fill and default icon; Designer's wrapper exposes success, warning, and error, while Info is available through the toolkit service), title (string, a short outcome in sentence case), message (string, an optional explanation or next step that wraps fully and is never truncated), icon (string, defaulting to the matching semantic icon in a 24px box, with an override allowed as long as its meaning matches the message), and className / appendTo (toolkit escape hatches for themed runtime content and a custom overlay host, not additional visual variants). Toast has four variants: Success confirms a completed action ("Stage saved" / "Your changes are ready to use."), Warning explains a recoverable condition that needs attention ("Some changes could not be applied" / "Review the affected fields before continuing."), Info shares a neutral update about an operation ("Export started" / "You can keep working while the file is prepared."), and Error explains a failed action and the next step ("Failed to load builds" / "Try again. If the problem continues, contact your administrator."). There is no visual state axis: hover and keyboard focus pause the timer without changing appearance, and the only state styling is the close button focus ring. There is no size axis either; Toast has one size and content determines its width and height, giving three content states, Title only, Title and message, and Message only, with no Small, Medium, or Large variants. Its anatomy consists of a borderless filled Container laid out horizontally with items vertically centered, 8px vertical and 16px horizontal padding, a 16px gap, an 8px corner radius, and a width that fits content up to a 1200px maximum; a TypeIcon in a 24x24 box that does not shrink; a Title in Open Sans 14px/22px weight 600 (SemiBold), visible when a title is provided; a Message in Open Sans 12px/18px weight 400 (Regular), visible when a message is provided, with no extra gap between title and message lines and the text column set to flex 1, min-width 0, and overflow-wrap anywhere; a trailing Close cross icon at 12x12 with a 24px minimum width and height, zero padding, and a focus-visible ring of 2px solid currentColor at 3px offset with a 2px radius; and a Stack that is always bottom center, 36px from the bottom edge, with 8px between items, newest at the bottom and older toasts above. The container shadow is 0 10px 24px 0 rgba(15, 17, 20, 0.1), exposed as --flowx-toast-shadow-color; it is the exact source shadow and has no match in the elevation scale (xs 0 2px 8px through xl 0 24px 32px, all #1634621a). Toast has no action slot, so no Button variant is reused.

In the light theme every variant uses white (#ffffff, --flowx-grays-50) for the icon, title, body, and close control, with no border, and only the fill changes: Success is #008060 (--flowx-green-500), Warning is #fd6b1c (--flowx-orange-500), Info is #3389e0 (--flowx-blue-400), and Error is #e62200 (--flowx-red-500). There is no dark override: the .dark theme does not redefine the palette tokens the toast uses, so on dark surfaces it renders exactly the same fills and white text, and a shared dark Toast treatment still needs separate review. White text contrast against each fill is 4.93:1 on Success, 2.88:1 on Warning, 3.62:1 on Info, and 4.57:1 on Error against a 4.5:1 target, so Warning and Info fall below it and the colors are documented, not certified as accessible. Toasts always appear at bottom center, 36px from the bottom edge, with 8px between toasts, the newest at the bottom and older messages stacked above, and the close button must stay reachable above fixed navigation or an on-screen keyboard; the documentation demo caps the stack at three, a limit that applies only to the demo. Every toast closes automatically based on content length: 50 milliseconds per character across the title and message, with a 2000ms minimum, a 3000ms minimum for errors, and a 10000ms maximum, so 20 characters give 2s (3s for Error), 80 characters give 4s, and 240 characters give 10s. Hover pauses the timer and resumes the remaining time on leave, preserving rather than restarting it, and the documentation also pauses for keyboard focus inside the toast, whereas Angular pauses only on hover. The close button is always available and removes only its toast before the timer finishes, clicking the toast body does not dismiss it, and toast actions are not supported because follow-up controls belong in the page. The entry animation runs 320ms with cubic-bezier(0.22, 1, 0.36, 1) from opacity 0, translateY(16px) scale(0.98) to opacity 1, translateY(0) scale(1); the exit animation runs 260ms with cubic-bezier(0.4, 0, 1, 1) from opacity 1, translateY(0) scale(1) to opacity 0, translateY(10px) scale(0.98), with pointer events disabled while exiting and removal after 260ms; prefers-reduced-motion: reduce disables both animations and removes the toast immediately. The Angular source instead uses a 300ms height entry and a 200ms height/opacity exit. Focus stays on the triggering control when a toast appears, and after dismissing a focused toast focus returns to a meaningful control.

Use a Success toast to confirm a completed action when the result is not obvious in the current view and name what changed; use Warning for a recoverable condition, giving enough context to act while keeping required corrections visible in the page; use Info to explain an event without implying success or failure, keeping progress for ongoing work in the page; and use Error to name the failed operation and a useful next step without exposing raw server errors. Do provide a title, a message, or both in sentence case, let long text wrap and grow vertically up to 1200px and the available viewport width, keep essential instructions and recovery controls available in the page after the toast disappears, use an inline message when information needs to remain visible, and keep any icon override consistent with the message. Don't truncate the title or message, don't put actions inside a toast, don't expose raw server errors, and don't silently replace the solid Warning (Orange 500) and Info (Blue 400) fills, which differ from the soft status-pill palette. For accessibility, use a status role for routine feedback and an alert role for important, time-sensitive failures, announcing updates without moving focus; Tab and Shift+Tab reach the close button and pause dismissal while focus is inside the toast, Enter and Space activate it, aria-atomic="true" announces the complete title and message together, the close control carries an aria-label such as "Dismiss notification", the decorative type and close icons are aria-hidden="true", and the documentation preview wraps each live toast in role="group" labelled "{Type} notification" while announcing non-error toasts through a status region and errors through an alert region. A 2 to 10 second timer alone does not establish accessibility; Angular lacks explicit live-region roles and focus pause, and React announces every type as an alert. The decision log records, on 2026-09-07, always using bottom-center placement, automatic timing, and a close button while omitting toast actions, because current design guidance limits Toast to brief feedback in a consistent location. Adoption notes, which are observed gaps rather than approved exceptions, record that React uses a 3-second minimum for Warning and Info compared with Angular's 2 seconds and does not pause on hover or focus, always schedules a timeout, marks every toast as an alert, and has no equivalent queue service; that Angular groups by the raw position value, so mixing an omitted position with an explicit bottom-center value can omit messages from an existing stack and the default must be normalized consistently; and that themed runtime overrides and a shared dark treatment still need review. Related components are button, input-field, and status-pills; related patterns are alerts and modals. Known gaps: no dark theme treatment, no verified Figma link, a shadow outside the elevation scale, Warning and Info contrast below 4.5:1, no action slot, no hover or pressed styling for the close button (only focus-visible), an Info icon drawn on a 16x16 viewBox scaled into the 24px box while the other three use 24x24, lowercase messageType values against capitalized variant names and data-toast-type values, preview-only entry and exit animations that differ from the Angular height animation, no source-defined maximum stack count, and no minimum width, minimum height, or fixed height.
